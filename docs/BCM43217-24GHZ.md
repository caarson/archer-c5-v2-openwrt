# BCM43217 2.4 GHz AP bring-up correction

The Archer C5 v2 could receive nearby networks and report `AP-ENABLED`, but clients could not use its 2.4 GHz AP. Transmit commands completed without peer acknowledgments. The external-PA gain table was absent, and the dedicated BCM43217 PA control-output mux was not configured.

## Correction

The b797 baseline is retained with targeted initialization changes for the BCM43217/N-PHY17, radio2057 revision14/version1 external-PA front end:

- Supply the vendor-matched 128-entry EPA gain table for the factory `extpa_gain=3` configuration.
- Route the PHY's normal external-PA control outputs using PMU ChipControl1 bits13/8 (`0x2100`), preserving other bits and the vendor board-flag exclusion.
- Configure the matching external detector/TSSI and AUXADC settings, calibrated RC filter handling and crystal path.
- Distinguish the radio's version nibble from its historical radio-ID field and use the version1 initialization/channel tables for channels1–11.
- Restrict the older external-LNA mux workaround to its original packages and retain the factory single-antenna CCK firmware flag.

No transmit-power target, factory calibration coefficient, saved NVRAM, DMA ownership, aggregation policy, rate-control policy, or AC-PHY packet-processing code is changed. The temporary N-PHY observers and header capture are excluded from the release source.

This extends existing b43 board/radio initialization. It is not a new PHY implementation or a proprietary `wl` driver port. The BCM4352 AC-PHY implementation still derives from Alessio Ferri’s b43-ac-wip; that data path and the CDC mac80211 companion are unchanged.

## Evidence and limits

The matched control failed to connect. The otherwise matched PA-routing candidate changed the observed control value from0 to`0x2100`, after which the Mac client associated, obtained DHCP and passed two-way application SHA checks and bound-interface internet access. This identifies the missing control routing as the final demonstrated transmit blocker; it does not independently establish the necessity or performance effect of every initialization correction.

The diagnostic-free driver was tested from a cleared hardware state. Its channel1 campaign remained associated and showed no persistent stall, kernel warning, memory-pressure event or critical AC ownership/DMA error. It completed29 full probe rounds and30 bidirectional128KiB application checks, plus the initial connection check. Two of60 ICMP replies were missed, and one single-attempt DNS query timed out. Both Archer and direct-Cox DNS then passed12/12 paired follow-up queries;19 resumed rounds needed no DNS retry. The strict campaign is **CONDITIONAL**, not a clean-pass or long-term stability claim. A final partial round was interrupted by owned endpoint cleanup and is excluded.

A nearby-network survey found very strong overlapping channel2 networks near the channel1 test and only a weak channel11 neighbor. The saved AP uses US channel11,20MHz/NOHT. Beacon RSSI is a channel-selection aid, not a measurement of channel utilization or proof of the earlier packet-loss cause. Post-install channel11 results are recorded in `evidence/bcm43217-post-install.json`.

The channel11 follow-up confirmed usable WPA2 association, DHCP, two-way application checks and internet access after a cold boot, with21 protected/module/configuration identity records matching. Intermittent ICMP/DNS loss and occasional six-second upload timeouts remain in the extended investigation. Additional RX-gain, TX-chain, software-CCMP and PHY17 base-initialization candidates did not establish a repeatable stability correction and were not promoted. An iPhone passed10/10 integrity rounds during the unpromoted PHY17 trial; that success must not be attributed to the installed4130 control. See the evidence file for the separated results. **Functionality is restored; full2.4GHz reliability is still unresolved.**

**2.4 GHz remains legacy802.11b/g in this build.** A54Mbps negotiated legacy rate is not application goodput or300Mbps802.11n support. No new throughput ceiling is claimed. The historical5GHz receive-load stall is not proven eliminated by this correction.

The published baseline source reproduced the b797 binary exactly after full recompilation and normalization of historical `__FILE__` build paths. GCC/ASan/UBSan and ARM compilation checked65,536 actual PA-selector/bit-preservation cases and16,384 actual AUXADC-selector/write-bound cases. The exported fixtures also pass native Apple Clang sanitizers. These tests do not establish RF or DMA hardware correctness.

The delta `patches/release/bcm43217-epa-initialization.patch` applies to the previous b797 source. The current `source/release-b43/` snapshot and aggregate baseline-to-qualified patch already contain it; do not apply overlapping patches cumulatively.

## Provenance and dependencies

Register and table facts were corroborated against the Archer C5 v2 [TP-Link GPL archive](https://static.tp-link.com/resources/gpl/Archer_C5_v2_gpl_code.tar.bz2), vendor907.111 object SHA256`ddc9f9f894d775a54fc1e8023fdc65b3edb83819be226b66d479a38632d63bf7`. The control-output definitions are also present in Broadcom’s [sbchipc.h](https://android.googlesource.com/kernel/common/+/bcmdhd-3.10/drivers/net/wireless/bcmdhd/include/sbchipc.h). Existing brcmsmac code corroborates the legacy package restriction.

The host driver remains GPL open source. Proprietary Broadcom N-PHY microcode666.2 and AC microcode784.2 remain dependencies; firmware blobs, vendor objects, credentials and per-unit calibration are not distributed here.

The private lab installation updates the matching driver persistently and enables the AP. It does not create a generic public flashable image or change the existing kernel, bootloader or calibration regions. The previous b797 module remains in the read-only base filesystem for rollback. This is still a device-specific source prerelease, not a public production-hosting certification.
