# Contributing

Useful first reviews are the installed-source provenance, original-layout integration/config drift, the persistent receive stall, and a clean reproducible build that excludes private provisioning. Keep correctness fixes separate from performance experiments.

Report the exact kernel/b43/firmware identities and device revision, a redacted wired-endpoint topology, traffic direction/rate/duration, CPU/memory, useful flow progress, association, and new kernel messages. Do not publish Wi-Fi passwords, SSH keys, public IPs, SSIDs, device MACs/serials, factory data, raw flash dumps or unredacted household captures.

Do not request uncontrolled stress on someone's production uplink. Any stall reproduction or candidate boot needs independent recovery and the device owner's explicit bounded approval. Compilation and capability flags alone do not establish hardware correctness or production readiness.

For discussion, use the project forum topic once announced; use repository issues for actionable, identity-specific source defects. Preserve upstream authorship and per-file licenses.
